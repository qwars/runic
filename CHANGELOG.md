## [1.3.0] - 2026-10-09

### 🚀 Производительность (Performance)

- **ThreadPool вместо `thread::spawn`**: Все IPC-запросы теперь выполняются в пуле из 8 рабочих потоков вместо создания нового потока ОС на каждый запрос. Устранено потребление памяти ~800 МБ при старте (было ~100+ потоков), снижено до ~30-50 МБ. Время отклика IPC сокращено с 10-50 мс до <1 мс.
- **Debouncing для директорий в `watch`**: Добавлен временной debounce 500 мс для событий директорий. Устранена лавина inotify-уведомлений, когда скрипты-обработчики сами генерируют события в отслеживаемой директории.
- **`try_send` вместо `send_blocking`**: Все каналы IPC теперь используют неблокирующую отправку. Устранены потенциальные deadlock'и при зависании GTK main loop или переполнении буфера канала.
- **Монотонные часы для детектора сна**: `SystemTime` заменён на `Instant` (монотонные часы). Детектор выхода из сна теперь корректно работает при переводе системных часов или NTP-синхронизации.

### 🛡️ Безопасность и надёжность (Security & Reliability)

- **Process Groups для корректного завершения `sh -c`**: Все команды, запускаемые через `sh -c` (exec, stream), теперь создаются в отдельной группе процессов (`setpgid`). При завершении вся группа получает `SIGTERM`/`SIGKILL` (`kill(-pid, ...)`). Дочерние процессы больше не остаются сиротами.
- **Устранены все предупреждения `cargo clippy -- -D warnings`** (включая замену `sort_by` на идиоматичный `sort_by_key` с `Reverse`).
- **Улучшена обработка ошибок**: все сообщения об ошибках и отладочная информация теперь используют строгую типизацию и безопасные методы.

### ✨ Добавлено (Added)

- **Профилирование ресурсов**: Встроенный сбор метрик использования памяти (VmRSS из `/proc/self/status`) и времени CPU (`getrusage`) для каждого IPC-запроса. Выводится только при превышении порогов (>100 мс или >1 МБ ΔПамяти или >50 мс ΔCPU).
- **Трекинг потоков (`ThreadTracker`)**: Комплексный мониторинг активных и завершённых фоновых потоков — пиковое потребление памяти, время жизни, количество выполненных задач. Предотвращает незаметное исчерпание ресурсов.
- **Цветной вывод в консоль**: ANSI-цвета для мгновенного визуального распознавания типов сообщений:
  - 🔴 **Красный** — Ошибки и STDERR дочерних процессов
  - 🟡 **Жёлтый** — Предупреждения и ошибки инициализации
  - 🟢 **Зелёный** — Успешный запуск процессов
  - 🔵 **Голубой** — Отладочная информация
  - 🟣 **Пурпурный** — Данные профилирования производительности
- **Расширенный набор тестов**: 15 комплексных модульных тестов, покрывающих все IPC-действия (`read`, `write`, `exec`, `stream`, `watch`, `unwatch`) и граничные случаи (пустые target, дубликаты, очистка ресурсов).
- **Полная локализация**: Все внутренние логи, сообщения об ошибках и отладочный вывод переведены на чистый, современный русский язык без англицизмов.

### ⚙️ Изменено (Changed)

- **Константы вместо магических чисел**: Все ключевые значения вынесены в именованные константы (`IPC_CHANNEL_SIZE`, `DIR_WATCH_DEBOUNCE_MS`, `THREAD_POOL_SIZE`, `WATCH_POLL_INTERVAL`, `STREAM_STATS_BATCH`, `WATCH_STATS_BATCH`, `TAIL_BUF_LIMIT`).
- **Периодический вывод статистики потоков** в режиме отладки (каждые 30 секунд) для удобного мониторинга состояния приложения в реальном времени.
- **Улучшена читаемость кода** за счёт введения констант для ANSI-цветов и интервалов таймеров.

## [1.2.0] - 2026-10-08

### 🛡️ Исправлено (Fixed)

- **Критическое**: Устранено состояние гонки TOCTOU (Time-of-Check to Time-of-Use) в действии `stream`. Проверка наличия запущенного процесса и его регистрация теперь выполняются атомарно под одним блокировщиком мьютекса.
- **Критическое**: Устранена паника (`unwrap()`) в действии `watch` при мониторинге директорий, если параллельно вызывался `unwatch`. Заменено на безопасный `insert`.
- **Критическое**: Устранена двойная отправка `SIGKILL` и вызов `waitpid` для одних и тех же PID в функции `kill_and_clear_tracked`. Теперь PID, уже обработанные через `running_streams`, исключаются из списка `spawned_pids` перед массовой очисткой.
- Заменены все небезопасные вызовы `.unwrap()` на `.lock()` мьютексов на использование функции `safe_lock`, что предотвращает панику приложения при отравлении (poisoning) мьютекса, особенно в обработчиках сигналов завершения (SIGTERM/SIGINT).

### ✨ Добавлено (Added)

- **Механизм корректного завершения (graceful shutdown)** фоновых потоков (`watch` и детектор сна системы) с использованием флага `AtomicBool`. Потоки теперь чисто останавливаются при закрытии приложения, а не остаются висеть в фоне.
- **Логирование ошибок выполнения JavaScript** (`run_javascript`) в режиме отладки (`--debug`).
- **Новые модульные тесты** для проверки исправленных уязвимостей:
  - `test_handle_action_stream_duplicate_error` (проверка блокировки повторного запуска stream)
  - `test_kill_and_clear_tracked_no_double_kill` (проверка отсутствия двойного убийства процессов)
  - `test_shutdown_flag_stops_watch_loop` (проверка остановки потока watch при shutdown)

### ⚙️ Изменено (Changed)

- Улучшена совместимость с более старыми версиями компилятора Rust (MSRV < 1.87): цепочки `let` (let chains) заменены на вложенные конструкции `if let`.
- Устранено предупреждение Clippy `lines_filter_map_ok`: использование `.flatten()` на итераторе `io::Lines` заменено на `.map_while(Result::ok)` для предотвращения потенциальных бесконечных циклов при ошибках чтения.
- Удалены случайные замыкающие пробелы в описаниях аргументов командной строки (`clap`).

## [1.0.0] - 2026-10-01

### ✨ Первый публичный релиз

- Базовый IPC-мост с 7 действиями: `read`, `write`, `exec`, `stream`, `unstream`, `watch`, `unwatch`.
- Интеграция с Layer Shell (Wayland).
- Прозрачный фон виджетов.
- Базовая очистка дочерних процессов при завершении.
